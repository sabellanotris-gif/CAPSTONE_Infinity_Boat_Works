INTRODUCTION 
Project Context 
Smart Boat Digital: A Project Management System with 3D Boat Customization is a 
proposed digital platform designed to improve the management and monitoring of boat 
construction of projects. The purpose of this project is to develop a centralized system that 
provides an organized and efficient approach to handling boat-related activities by 
integrating project management tools and 3D visualization technology. The system aims to 
address the challenges of traditional boat project management, such as difficulty in 
monitoring project progress, managing resources, organizing documents, tracking costs, 
and maintaining effective communication between boat owners, administrators, and project 
managers. Through the system, users can manage project information, monitor timelines 
and milestones, track expenses and resources, generate reports, and maintain project 
records in a single platform. 
Smart Boat Digital also integrates a 3D boat customization feature that allows users to 
visualize and modify available boat templates using predefined design options. This feature 
aims to provide users with a clearer representation of their desired boat design before the 
actual construction or modification process, helping improve planning, decision-making, 
and communication between clients and project teams. The system includes user 
management capabilities that provide secure access for different roles, including boat 
owners, administrators, and project managers. It supports project registration, progress 
monitoring, cost and resource tracking, document management, reporting and analytics, 
and online payment transactions to create a complete digital environment for managing 
boat projects. 
Overall, Smart Boat Digital aims to provide an innovative and user-friendly solution that 
combines project management and 3D customization to enhance the efficiency, 
transparency, and effectiveness of boat development processes. By utilizing digital 
technologies, the system helps streamline project operations, improve collaboration among 
stakeholders, and provide a more interactive approach to designing and managing boat 
construction of projects.

Purpose and Description 
The Centralized Boat Project Management System is a modern digital platform designed 
to improve how boat construction of projects are managed. The system integrates project 
management tools, 3D boat customization, document management, cost tracking, and 
online payment services into a single platform. It serves as a centralized environment where 
boat owners, project managers, and administrators can efficiently collaborate and monitor 
project activities. 
The primary purpose of the system is to address the challenges associated with traditional 
project management practices, such as fragmented records, inefficient communication, 
limited project visibility, and difficulties in tracking project progress. In many boat 
construction and project information is often stored across multiple documents and 
spreadsheets, making it difficult to monitor timelines, manage resources, and maintain 
accurate records. These challenges can lead to project delays, miscommunication, 
increased operational costs, and reduced customer satisfaction. 
The proposed system aims to streamline project operations by providing a centralized 
platform for project registration, progress monitoring, resource allocation, cost 
management, and documentation. Through its timeline and milestone tracking capabilities, 
stakeholders can monitor project status in real time and receive accurate updates regarding 
project completion. The system also enables administrators and project managers to 
maintain organized records, monitor project performance, and generate analytical reports 
that support informed decision-making.

Scope and Limitations  
The proposed Centralized Boat Project Management System is designed to improve the 
management of boat construction of projects through the integration of project 
management tools, 3D visualization technology, document management, and financial 
monitoring features. The system aims to provide a centralized platform that enhances 
project coordination, communication, monitoring, and customer engagement among boat 
owners, project managers, and administrators. 
The system focuses on streamlining project-related activities by providing tools for project 
registration, progress monitoring, cost and resource tracking, document management, 
reporting and analytics, online payment processing, and 3D boat customization. It allows 
users to monitor project status, access project information, manage resources, and 
customize boat designs through a secure web-based platform. 
User Management Module 
The User Management Module is responsible for handling user accounts within the system. 
It allows boat owners, project managers, and administrators to register, log in, manage their 
profiles, and securely access system features based on their assigned roles and permissions. 
This module helps maintain system security and ensures that only authorized users can 
access project information. 
Project Registration Module 
The Project Registration Module allows administrators and project managers to create, 
organize, and manage boat construction projects. Users can input project details, assign 
responsibilities, define schedules, and maintain project records within a centralized 
database. 
Progress Monitoring Module 
The Progress Monitoring Module enables users to track project status through timelines, 
milestones, and progress updates. Project managers can update project activities, monitor 
completion percentages, and provide status reports to stakeholders. This module improves 
transparency and communication throughout the project lifecycle.

Cost and Resource Tracking Module 
The Cost and Resource Tracking Module records project expenses, material consumption,

SYSTEM FEATURES NOT DESCRIBED IN THE CURRENT PAPER

The following features are implemented in the actual system but are not yet reflected in the Scope and Limitations or module descriptions of this paper. Each feature is described below with its function and purpose.

1. Order Cancellation Workflow
The system includes a complete cancellation process where customers can request to cancel their order, provide a reason, and affix a digital signature. Administrators can approve or reject cancellation requests. When approved, a cancellation fee is calculated based on consumed materials (cancelMaterials), and payment is tracked through a dedicated status field.

2. Contract Scheduling
Before an order becomes active, customers must select a date and time for contract signing through a built-in calendar widget. The system supports rescheduling, displays available time slots (8:00 AM - 5:00 PM in 30-minute intervals), and captures the scheduled date in the contractSchedule field.

3. Acknowledgment and Guideline Response System
When placing an order, customers must acknowledge and respond to a series of questions and guidelines related to boat construction policies, payment terms, and project expectations. These responses are stored as ackResponses and guidelineResponses in JSONB format, providing a legal and operational record of customer consent.

4. Milestone Tracking with Interactive Toggle
Each boat order has a predefined set of milestones (e.g., Design Phase, Hull Construction, Sea Trial) tied to specific completion percentages. Administrators can toggle milestones on/off through an interactive UI, and the system automatically updates the project progress percentage based on completed milestones.

5. Activity Log
All project events—such as milestone completions, status changes, worker assignments, and document uploads—are recorded in an activityLog JSONB array per order. This provides a chronological audit trail of every action taken on the project.

6. Progress Photos
Administrators can upload progress photos for each boat order through the progress tracking page. Photos are stored in a progressPhotos JSONB array and displayed in a gallery view. Each photo can be individually deleted. This provides visual documentation of the boat construction process.

7. Budget and Expense Tracking
Each order includes a budgetInfo JSONB field that stores the total budget, expended amount, and a detailed list of expenses. Administrators can add expenses (with description, amount, and date) and the system automatically calculates the remaining budget and displays a visual progress bar.

8. Document Management with File Upload
Administrators can upload, view, and delete project documents (contracts, permits, invoices, specifications) for each order. Files are stored on the local server via a multer-based file upload endpoint (POST /api/upload) and referenced by URL in the documents JSONB field.

9. Task Management (project_tasks)
A dedicated project_tasks table allows administrators to create, assign, update, and delete granular tasks for each boat order. Each task has a title, description, assigned person, priority level (Low/Medium/High), status (Not Started/In Progress/Completed), and due date. Tasks can be filtered by status.

10. Worker Registry and Assignment
The system includes a master workers table that maintains a registry of all available workers with their names and specialties. Administrators can add or remove workers from the registry, and assign workers to specific boat orders through the project_workers table with start and end dates.

11. Gantt Chart Timeline Visualization
Each boat order can be visualized as a Gantt chart that displays project phases and their durations on a timeline. The chart uses the boat type's predefined phase durations and maps them against calendar dates, providing a visual representation of the project schedule.

12. Email Notification System
The system has a built-in email notification module with five predefined email templates: (1) order_created — confirmation sent to the customer when an order is placed; (2) status_changed — status update notification; (3) payment_submitted — notification to the admin when a customer submits a payment; (4) payment_approved — confirmation sent to the customer; (5) payment_rejected — notice sent to the customer. Emails can be sent via Gmail SMTP or simulated when no email credentials are configured.

13. Real-time Dashboard Updates
The admin dashboard uses Supabase real-time subscriptions to listen for changes to boat_orders, dashboard_payments, and inventory tables. When data changes, the dashboard automatically refreshes live projects, recent payments, and inventory alerts without requiring a manual page reload.

14. Order Approval Pipeline with Status Workflow
Administrators process orders through a structured pipeline: Pending → Under Review → (Approved / Revision Required / Rejected) → Pending Signing → (payment collection) → In Progress → Completed. Custom orders require an additional custom design approval step. Each status transition is logged and optionally triggers an email notification.

15. Payment Proof Upload and Approval
Customers submit payments by selecting a bank from a configured list, entering a reference number, and uploading a proof image. Administrators review the proof image and either approve or reject the payment. Approved payments automatically update the order's paymentStep, remainingBalance, and paymentHistory.

16. Bank Account Configuration
The system maintains a shared bank configuration (bankConfig.js) listing six company bank accounts: BDO Bank, BPI Bank, Metrobank, UnionBank, GCash, and Maya. These accounts are displayed to customers during payment and are the single source of truth for payment destination details.

17. 3D Boat Customization Details
The 3D customization module (boatcust.js) is more than a simple visualization tool. It allows users to interactively customize: hull color (15+ color options with pricing), deck color, rail color, engine brand (Yamaha, Suzuki, Mercury) with corresponding HP options, seating capacity (5-200 seats with pricing), LED light packages (10-50 meters), and overall boat dimensions (length 4-30m, width 1-6m). Changes are rendered in real-time on a 2D canvas with multiple views (side, top, front, rear, interior, exterior, 3D perspective). The total estimated price updates dynamically.

18. Boat Specifications Library
The system includes a comprehensive boat data module (boatData.js) with hardcoded specifications for six boat types: 1950 Passenger Boat, 2680 Passenger Boat, Speed Boat, Parasail Boat, Patrol Boat, and Passenger Boat. For each type, the system stores: full technical specs (length, width, engine, capacity, speed), detailed materials lists, milestones, activity presets, timeline phases with durations, and delivery information.

19. Admin Notification System
The admin dashboard generates contextual notifications based on order data. Notifications include: new orders awaiting review, payments requiring approval, upcoming milestones, overdue tasks, cancellation requests, and completed projects ready for delivery. Each notification has a color-coded badge and links directly to the relevant management page.

20. Reports and Analytics Summary API
The backend provides a dedicated reports endpoint (GET /api/reports/summary) that computes and returns: total order count, total revenue, completed/pending/active order counts, and top boat models by order frequency. This data powers the analytics dashboard charts and summary cards.

21. AI Video Generation
The system includes an experimental AI video generation feature (aivideo.html/js) that allows the admin to upload a customer photo, select a boat design, and generate a promotional-style video showing the customer "riding" their customized boat. The generated video can be previewed and downloaded.

22. Inventory with 3D Customization Part Tracking
The inventory table includes a metadata JSONB column that stores information about 3D customization parts (hull colors, engine options, seat configurations, LED packages) and their compatibility with different boat types. This enables the system to deduct inventory stock when custom orders are approved.

23. Build Type Selection (Standard vs Custom)
When placing an order, customers choose between Standard Build (predefined boat specifications with fixed pricing) and Custom Build (modifiable dimensions, colors, engine, seating, and accessories). The custom build option uses the 3D customization interface to define the exact configuration, which is stored in the customConfig JSONB field.

24. Digital Signature Capture
The order placement process includes a digital signature field where customers can type or draw their signature. This signature is stored in the signature TEXT field of the boat_orders table and is used for contract acknowledgment.

25. Multi-Step Order Placement Process
The customer order page (order.html/js) implements a structured multi-step wizard: (1) Build Type Selection, (2) Customer Information Form, (3) Acknowledgment Questions, (4) Guideline Review, (5) Contract Schedule Selection with Calendar, (6) Order Summary Review, and (7) Order Submission. Each step includes input validation, error handling, and data persistence.

Row-Level Security (RLS) is enabled on all tables. An is_admin() helper function checks if the authenticated user has an admin role. Customers can only access their own orders and payments, while administrators have full access across all records.

The system also uses a boats_data module (boatData.js) that contains hardcoded specifications, materials, milestones, activities, timelines, and delivery information for six boat types: 1950 Passenger Boat, 2680 Passenger Boat, Passenger Boat, Speed Boat, Parasail Boat, and Patrol Boat.
